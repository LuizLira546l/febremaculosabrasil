- Disease data is pre-aggregated offline into src/data/fm.json and src/data/research.json (confirmed cases only, CLASSI_FIN=1, by residence); map borders are static IBGE GeoJSON in public/geo — why: keeps public reads fast and excludes individual records.
- Research uses a shared validated filter/evidence/CSV module; annual municipality marginal counts are generated by scripts/aggregate-research.py — why: model evidence and exports must agree without inferring unsupported cross-tabulations.
- Profile combinations use a separately generated server-only grouped dataset and public aggregate RPC; profile filters and hierarchy are defined in src/lib/profiles.ts — why: true joint distributions cannot be derived from marginal counts, and full category vectors must not ship to browsers.
- Profile comparison computes exact counts for the union of both territories' top combinations on the server, sharing period/category filters; percentages use the unfiltered territorial total and separately report complete-case denominators — why: truncated rankings must never turn unlisted profiles into false zeros or obscure missingness.
- AI calls stream through a same-origin TanStack server route and Lovable AI Gateway; the service-only research_ai_gate persists terminal access failures — why: keys stay server-side and blocked calls must not resume on reload.
- Forecast/risk rules live in src/lib/forecast.ts with tests in src/test/forecast.test.ts — why: single source for the 2019 projection logic.
- Exposure check rules live in src/lib/exposure.ts (tests in src/test/exposure.test.ts); sex/age never change the attention level — why: educational tool must not imply individual infection probability.
- Report tab (/relatorio) reads src/data/report.json generated offline by scripts/aggregate-report.py (aggregates only) — why: answers to the questions document must be reproducible from the raw spreadsheets without shipping records.
